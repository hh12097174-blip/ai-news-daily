## 一、30 秒电梯演讲（背熟）

> "我做了一个基于 Hermes Agent 的多 Agent 协作系统，它能每天自动完成**选题采集 → 智能评估 → 原创撰写 → 质量审核 → 发布上线**整个博客生产流程，全程无人值守。
>
> 核心设计三块：第一，**6 个角色分工协作**，每个角色独立人格、独立模型、最小化工具权限；第二，**Cron + 依赖链**串行调度，前一阶段输出自动成为后一阶段输入；第三，**Docker 容器隔离**执行所有命令，宿主机零风险。
>
> 我还自研了一个来源评分插件，给每条新闻打可信度分，让系统有质量把关。文章最终自动发布到 GitHub Pages，你可以直接访问在线博客。"

## 二、3 分钟深度讲解（面试官追问时展开）

### 2.1 系统是什么（30 秒）

每天 07:00 起，6 个 Agent 角色按依赖链串行工作：collector 抓 HN/IT之家候选选题 → analyst 用我写的 score_source 插件评分选 3 个 → editor 用更强模型写 1500-3000 字原创文章 → reviewer 按清单审核 → pusher git 提交发布到 GitHub Pages。09:00 还有一个零成本的纯脚本健康检查。

### 2.2 亮点一：Agent 自主决策（重点讲）

- 系统不是写死的 if-else 流水线，是**让模型自己判断**怎么干活
- 例：web_search 工具不可用时，Agent 自动 fallback 到 terminal + curl 抓取——这是模型自主决策，不是代码分支
- 例：reviewer 发现容器内读不到宿主文件，自己给出"挂载路径或 context_from"的专业诊断
- **证明你理解"Agent 是决策者，不是执行器"**

### 2.3 亮点二：容器化安全隔离（重点讲）

- Agent 框架最大风险：提示词注入 → 恶意命令
- 三层防御：Docker 容器隔离（所有命令在容器跑）+ Hook 黑名单拦截（rm -rf 等）+ Profile 最小权限
- 实测：容器内主机名是容器 ID（cea4948c7e89），系统是 Debian——证明命令真在隔离环境执行
- 对比：课件/大多数案例没有容器隔离，这是我的差异化

### 2.4 亮点三：编排与依赖链

- context_from 强依赖链：任务串行执行，杜绝"下游抢跑读不到上游数据"（这是真实踩过的坑）
- orchestrator + Kanban auto_decompose：复杂任务自动拆解为多角色子任务图
- 多模型差异化：editor 用写作更强的 Qwen3，其余用便宜的 DeepSeek

### 2.5 排障故事（加分）

- 容器隔离导致任务间文件传递失败 → 诊断 → 挂载宿主目录解决
- Gateway 多实例 PID race → 锁文件清理流程
- 每个都展示了你"从现象到根因"的排查能力

## 三、常见问题 Q\&A

**Q1：为什么用 Hermes 不用 LangChain？**  
Hermes 是完整的 Agent 操作系统（内置 Cron/Kanban/Gateway/插件体系/记忆），LangChain 只是编排库。我关注的是**多 Agent 协作的工程化**（调度、看板、隔离、发布），不是拼 prompt。

**Q2：这跟 Copilot/WorkBuddy 这类现成工具有什么区别？**  
它们是通用助手；我搭的是**可编排的自动化系统**——角色、依赖链、审核、发布全链路自运转。价值在工程架构，不在"能用 AI"。

**Q3：怎么保证文章质量？**  
两道把关：score_source 插件（来源可信度 0-100 分）+ reviewer 角色（技术准确性/原创性/时效性清单审核），不达标 [BLOCK] 打回，不发布。

**Q4：容器隔离是摆设吗？**  
不是。实测证明命令真在容器执行；容器不持久化（用完即销毁）、不挂载宿主目录（我配置了 E 盘挂载给数据读写，但权限收敛）。是生产级的安全实践。

**Q5：为什么 5 个角色不是 1 个？**  
单一 Agent 上下文会膨胀、职责会混乱。角色分离带来：独立人格（SOUL）、独立模型（便宜/贵混用）、最小权限（各管一段）。这是多 Agent 的核心价值。

**Q6：context_from 和普通文件传递区别？**  
文件传递是"读文件"，有路径/权限/时序问题（我踩过坑）；context_from 是框架级依赖注入，保证上游完成才触发下游，数据准确传递。

**Q7：线上跑过吗？有什么真实产出？**  
跑过完整闭环：真实抓取 HN → 评分选题 → 写出原创文章（Cerebras 芯片深度解析）→ 审核通过 → 发布 GitHub Pages。仓库和在线博客都可以看。

**Q8：如果 Agent 被恶意 prompt 注入怎么办？**  
三层：容器隔离（恶意命令只影响容器）、Hook 黑名单（rm -rf 等直接拦截）、最小权限（无权限执行的工具即使注入也用不了）。纵深防御。

**Q9：每天跑要花多少钱？**  
DeepSeek-V4-Flash 极便宜（百万 token 几块钱），一次全流程约几十万 token，成本几分钱。健康检查用 No-Agent 纯脚本，零成本。

**Q10：项目里哪些是你写的？**  
score_source 插件（Python，评分算法）、5 个 SOUL.md 人格、危险命令 Hook 脚本、流水线调度设计、整个排障过程。框架是开源的，业务逻辑和工程架构是我的。
